# 2026-10-06 (화)

## 오늘 한 것

Gemini API 키를 발급받고 `.env` 파일에 보관했다.  
`.env`가 GitHub에 올라가지 않도록 `.gitignore`에 `.env`를 추가했다.  
Git Bash에서 `curl`을 사용해 Gemini API에 요청했고, 모델 목록이 정상적으로 응답되는 것을 확인했다.

## 찾아보고 알게 된 것

### API 키는
API를 사용할 때 사용자를 확인하고 API 사용 권한과 사용량을 관리하기 위해 필요하다.

### 무료 등급은
정해진 사용량과 요청 횟수까지 API를 무료로 사용할 수 있는 방식이다. 무료이지만 사용량 제한이 있을 수 있다.

### 보안 담당자가 다루는 서버는
Linux 계열 운영체제가 많이 사용된다. 안정적이고 서버 운영과 자동화에 필요한 환경을 갖추고 있기 때문이다.

### Git Bash를 쓰면
Windows에서도 Linux와 비슷한 명령어와 환경을 사용할 수 있어 서버 환경에서 사용하는 명령어를 연습하기 편하다.

## 키가 틀렸을 때와 키가 없을 때의 차이

키가 틀리면 인증에 실패하고, 키가 없으면 API가 요청을 인증할 수 없다.  
둘 다 정상적인 API 요청이 되지 않지만, 서로 다른 인증 문제라는 것을 알게 되었다.

## 막힌 것

AI Studio에서 처음에는 Apps 화면으로 들어가 API 키 발급 화면을 찾는 데 시간이 걸렸다.  
API Keys 화면에서 프로젝트를 선택해야 했고 `Default Gemini Project`를 선택해서 키를 생성했다.

또한 API 키를 확인하는 과정에서 **실수로 키를 채팅에 노출시키는 일이 있었다.** API 키는 비밀번호처럼 취급해야 하며, 앞으로는 키 자체를 공유하지 않고 `.env`에만 보관해야 한다는 점을 다시 확인했다.
