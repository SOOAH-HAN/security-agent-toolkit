## 5교시 · 설정 파일이 고장 나도 거부하기

### 문제 5-1 · 설정 파일을 안전하게 읽는 함수 `load_json` 만들고, 고장 두 가지로 시험하기

- (가) 실행한 출력 전체를 붙여 넣고, 경고 두 줄이 각각 어떤 오류 때문에 나왔는지 적어 주세요.
  - 쓸 내용: ① 출력 전체 ② 경고 두 줄이 각각 어떤 오류 때문에 나왔는지
  - 답:

```
config/users.json -> 사용자 6 명을 읽음, 판정을 계속한다
[경고] 설정 파일 없음: config/users_typo.json
config/users_typo.json -> 사용자 0 명, 등록된 사용자가 없다
[경고] 설정 파일 깨짐: config/users_broken.json
config/users_broken.json -> 사용자 0 명, 등록된 사용자가 없다
```
[경고] 설정 파일 없음: config/users_typo.json 파일이 존재하지 않아 FileNotFoundError가 발생했습니다.

[경고] 설정 파일 깨짐: config/users_broken.json의 JSON 문법이 잘못되어 json.JSONDecodeError가 발생했습니다. 마지막 항목 뒤에 쉼표가 있는 것이 원인입니다.

- (나) 🔍 실패했을 때 프로그램을 멈추지 않고 빈 설정을 리턴하는 것이, 오류로 멈추는 것보다 왜 안전한가요? 「멈춘 뒤 현장에서 생기는 일」을 넣어 적어 주세요.
  - 쓸 내용: ① 빈 설정을 리턴하는 이유 ② 멈춘 뒤 현장에서 생기는 일
  - 답:
정 파일을 읽지 못했을 때 프로그램이 오류로 종료되지 않고 빈 설정을 반환하면, 오류 상황에서도 프로그램이 예외 처리를 통해 정해진 방식으로 동작할 수 있습니다. 반대로 프로그램이 갑자기 멈추면 운영자가 문제를 확인하고 복구할 때까지 정산 업무가 중단되고, 담당자가 업무를 처리하지 못하거나 다음 업무까지 지연될 수 있습니다.
- (다) 🔍 설정 파일이 깨져서 모두 거부되면 정산 업무가 멈춥니다. 운영자가 이 상황을 빨리 알고 복구하려면 판정 프로그램에 무엇을 더하겠습니까? 두 가지 이상 적고, 그중 가장 먼저 할 것을 고른 이유를 적어 주세요.
  - 쓸 내용: ① 더할 것 두 가지 이상 ② 가장 먼저 할 것과 그 이유
  - 답:
첫째, 설정 파일을 읽지 못했을 때 경고뿐 아니라 오류 발생 시각과 파일 경로를 로그에 기록하도록 하겠습니다. 둘째, 설정 파일을 읽지 못하거나 모든 요청이 거부되는 상황이 발생하면 운영자에게 알림을 보내도록 하겠습니다. 셋째, 설정 파일의 문법과 필수 항목을 미리 검사하는 기능을 추가하겠습니다.

이 중 가장 먼저 오류 로그 기록 기능을 추가하겠습니다. 오류가 발생한 시각과 파일 경로를 확인하면 문제가 언제, 어떤 파일에서 발생했는지 빠르게 파악할 수 있어 원인 분석과 복구에 도움이 되기 때문입니다.

## 6교시 · 테스트 케이스 설계

### 문제 6-1 · 꼭 지켜야 할 네 가지를 테스트로 설계하고, 팀원의 제안을 시험하기

- (가) `test_policy_extra.py` 를 실행한 출력 전체를 붙여 넣고, 실패한 줄 번호와 `AssertionError:` 뒤에 나온 글자를 적어 주세요.
  - 쓸 내용: ① `test_policy_extra.py` 출력 전체 ② 실패한 줄 번호 ③ `AssertionError:` 뒤의 글자
  - 답:

```
5 통과
Traceback (most recent call last):
  File "C:\Users\User\security-agent-toolkit\access_control\test_policy_extra.py", line 14, in <module>
    assert ok == True, "6. 만료 정각에도 허용되어야 한다(팀원 제안)"
           ^^^^^^^^^^
AssertionError: 6. 만료 정각에도 허용되어야 한다(팀원 제안)
```
② 실패한 줄 번호: 14번 줄

③ AssertionError: 뒤에 나온 글자:

6. 만료 정각에도 허용되어야 한다(팀원 제안)

- (나) 🔍 그 실패는 코드가 틀렸다는 뜻인가요, 제안이 우리가 정한 만료 규칙과 다르다는 뜻인가요? 근거를 적어 주세요.
  - 쓸 내용: ① 코드가 틀렸는지, 제안이 정책과 다른지 ② 우리가 정한 만료 규칙과 3번 테스트 결과를 근거로 한 이유
  - 답:
이번 실패는 코드가 틀렸다는 뜻이라기보다, 팀원의 제안이 우리가 정한 만료 규칙과 다르다는 뜻입니다.

우리가 정한 규칙은 예외 권한이 만료되는 시각까지가 아니라, 만료 시각 전까지만 허용하는 것입니다. 실제로 3번 테스트에서 17:59에는 허용되고 18:00 정각에는 거부되는 것을 확인했습니다. 따라서 18:00에도 허용하자는 팀원의 제안은 기존 정책과 다르므로, 정책 코드를 바로 수정해서는 안 됩니다.

- (다) 🔍 정책 코드를 바꿀 때마다 `test_policy.py` 의 1 ~ 4번 테스트를 돌리지 않으면 어떤 사고가 날 수 있나요? 네 개 중 하나를 골라, 그 테스트가 막아 주는 사고를 구체적인 장면으로 적어 주세요.
  - 쓸 내용: ① 고른 테스트 ② 그 테스트가 막아 주는 사고 장면
  - 답:
3번 만료 경계 테스트를 선택하겠습니다.

예외 권한이 18:00에 만료되도록 설정되어 있는데, 정책 코드를 수정하면서 만료 시각까지 허용하도록 조건을 잘못 변경할 수 있습니다. 이때 테스트를 실행하지 않으면 만료된 사용자가 18:00 정각에도 정산 정보를 조회할 수 있습니다. 만료 전과 정각의 결과를 확인하는 3번 테스트는 이러한 권한 오남용을 방지하는 데 도움이 됩니다.
