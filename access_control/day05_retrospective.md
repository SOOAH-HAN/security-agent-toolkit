# 4교시 · 상황 3~8 정리

## 상황 3 · 다른 팀 업무를 잠시 지원함
- 원인: 사람의 일 때문에 일시적으로 필요한 권한이 생김
- 고칠 파일: `config/exceptions.json`
- 어떻게 고치나요: 지원 기간이 정해진 권한은 예외로 추가하고, 기간이 끝나면 예외를 삭제함
- 고친 뒤 확인: 만료 시각 전에 요청이 허용되고, 만료 후에는 다시 거부되는지 확인
- 더 써 보고 싶은 것(선택): 지원 업무가 계속 필요하면 역할을 바꾸는 쪽으로 정리

## 상황 4 · 새 권한이 필요함
- 원인: 요청 절차가 없어서, 권한을 누가 승인했는지 기록이 남지 않음
- 고칠 파일: `req_create.py`, `req_review.py`, `req_grant.py`
- 어떻게 고치나요: 요청서를 만들고, 다른 사람이 승인한 뒤, 승인된 요청만 권한을 부여함
- 고친 뒤 확인: 요청 상태가 `reviewing -> approved -> granted` 로 바뀌는지 확인
- 더 써 보고 싶은 것(선택): 본인 승인 방지, SLA 시간 초과 알림

## 상황 5 · 안 쓰는 권한이 쌓임
- 원인: 오래 안 쓰는 권한이 남아 있고, 회수 제외 기준이 없음
- 고칠 파일: `review_unused.py`, `config/exclude_list.json`
- 어떻게 고치나요: 90일 이상 안 쓴 권한을 후보로 뽑고, 필요한 경우 제외 리스트에 추가함
- 고친 뒤 확인: 사용자별 회수 후보와 제외 목록이 정확히 나오는지 확인
- 더 써 보고 싶은 것(선택): 사용 이력 없는 권한도 언제 회수할지 기준을 정리

## 상황 6 · 민감한 권한을 회수해야 함
- 원인: 회수 대상이 남아 있거나, 쓰기 권한 회수에 승인이 필요함
- 고칠 파일: `config/exceptions.json`, `config/users.json`, `revoke_approve.py`
- 어떻게 고치나요: 예외 삭제, 퇴사자의 역할 제거, 승인된 회수 계획만 실행함
- 고친 뒤 확인: 회수 이력과 실제 권한 판정이 일치하는지 확인
- 더 써 보고 싶은 것(선택): 회수 실패 원인과 승인 거절 사유를 이력에 남기기

## 상황 7 · 새벽 외부 접속, 그리고 정상 직원이 계속 거부됨
- 원인: 규칙이 현실 업무와 맞지 않거나 조건이 빠져 있음
- 고칠 파일: `config/conditions.json`
- 어떻게 고치나요: 권한별 업무 시간과 허용 접속 위치를 정하고, 필요한 경우 기준을 조정함
- 고친 뒤 확인: 통상적인 업무 시간의 요청은 허용되고, 위험한 외부/새벽 요청은 거부되는지 확인
- 더 써 보고 싶은 것(선택): 직원별 기준과 부서별 기준을 나누는 방식 검토

## 상황 8 · 매주 어긋남을 확인해야 함
- 원인: 사람이 로그를 눈으로 보고, 기준이 달라서 놓치기 쉬움
- 고칠 파일: `checklist.py`, `log_summary.py`, `weekly_report.py`, `config/alert.json`
- 어떻게 고치나요: 점검 · 집계 · 보고서를 같은 기준으로 자동화하고, 경고 기준을 설정 파일로 분리함
- 고친 뒤 확인: 매주 같은 출력 형식으로 거부율, 점검 실패, 조치 대상이 나오나 확인
- 더 써 보고 싶은 것(선택): 서버가 멈췄는지 로그가 비어 있는지까지 함께 감시

---

## 한 줄 정리
- 데이터 문제는 사용자/예외 같은 실제 값이 틀린 경우
- 규칙 문제는 허용 기준이 현실과 맞지 않거나 빠진 경우
- 규칙을 잘못 고치면 전체 요청에 영향을 주므로 더 위험함
- 결국 원인부터 분리해서 “데이터 수정/규칙 수정/절차 추가”를 구분해야 함
