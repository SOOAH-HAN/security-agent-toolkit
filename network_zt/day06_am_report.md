### 문제 3-1 · 권한 변경 판단 함수의 점수 직접 정하기

```
HEALTH_POINTS = 50

if account["role"] != "account_admin":
    return "거부", ["관리자 역할이 아님"]

if req["mfa"] == False:
    score = score + MFA_POINTS
    reasons.append("MFA 안 함")
```

- (나) 🔍 실행해서 나온 요청 A ~ F 의 결정을 적어 주세요. 모두 기대 결정과 같은지도 함께 적어 주세요.
  - 쓸 내용: 「A: … / B: … / C: … / D: … / E: … / F: …」 여섯 개와 「기대 결정과 같음 · 다름」
  - 답:
  요청	기대	실	일치 여부
A	허용	허용	일치
B	거부	거부	일치
C	추가확인	추가확인	일치

E	추가확인	추가확인	일치

- (다) 🔍 점수 세 개를 정하면서 찾은 조건을 적어 주세요. 점수 하나가 가질 수 있는 범위와, 두 점수의 합이 만족해야 하는 조건이 있나요?
  - 쓸 내용: ① 기기 보안 상태 이상 점수의 범위 ② MFA 점수와 해외 점수의 범위 ③ 둘의 합이 만족해야 하는 조건과 그 이유(요청 몇 번 때문인지)
  - 답:
  1. HEALTH_POINTS: 50점 이상
   - D 요청은 기기 보안 상태 이상만 발생한다.
   - D의 기대 결과가 거부이므로, 위험 점수는 최소 50점이어야 한다.
2. MFA_POINTS: 10점 이상 50점 미만
   - C 요청은 MFA 미사용만 발생한다.
   - C의 기대 결과가 추가확인이므로, 점수는 10점 이상 50점 미만이어야 한다.
3. COUNTRY_POINTS: 10점 이상 50점 미만
   - E 요청은 해외 접속만 발생한다.
   - E의 기대 결과가 추가확인이므로, 점수는 10점 이상 50점 미만이어야 한다.

4. MFA_POINTS + COUNTRY_POINTS: 50점 이상
   - F 요청은 MFA 미사용과 해외 접속이 동시에 발생한다.
   - F의 기대 결과가 거부이므로, 두 점수의 합은 50점 이상이어야 한다.
따라서 HEALTH_POINTS = 50, MFA_POINTS = 20, COUNTRY_POINTS = 30으로 설정하면 모든 조건을 만족한다.

- (라) 🔍 기기 보안 상태 이상은 정산 조회에서는 추가확인인데 권한 변경에서는 거부입니다. 왜 기준이 다른가요?
  - 쓸 내용: ① 정산 조회에서 그 신호의 점수와 결정 ② 내가 정한 권한 변경 점수와 결정 ③ 기준이 다른 이유
  - 답:
일반 정산 판단에서는 기기 보안 상태 이상에 40점을 부여하고, 20점 이상이면 추가확인, 50점 이상이면 거부하도록 설정했다. 따라서 기기 보안 상태 이상만 발생하면 40점으로 추가확인이 나온다.
반면 관리자 권한 변경은 중요한 권한을 변경하는 작업이므로 더 엄격한 판단이 필요하다. 이번 문제에서는 기기 보안 상태 이상에 50점을 부여해 해당 위험 신호 하나만으로도 거부되도록 설정했다.
즉, 작업의 위험도에 따라 점수와 판단 기준을 다르게 설정할 수 있다.

### 문제 3-2 · 요청 7건을 한꺼번에 판정해 건수 세기

- (가) 실행해서 나온 출력 전체를 붙여 넣어 주세요.
  - 쓸 내용: 거부 · 추가확인 줄, 건수 줄, 이유별 건수 줄 전체


- (나) 🔍 거부된 요청 중 필수 조건에서 바로 거부된 것과 점수가 쌓여서 거부된 것은 각각 몇 번 요청이고 이유가 무엇인가요?
  - 쓸 내용: ① 필수 조건으로 거부된 요청 번호와 이유 ② 점수로 거부된 요청 번호와 이유 목록
  - 답:
3번: 계정에 등록된 기기가 아님
4번: 재직 중인 계정이 아님
7번: 계정에 등록된 기기가 아님
점수가 쌓여 거부된 요청: 1건
- 6번: 해외 접속 30점 + 새벽 접속 20점 = 총 50점으로 거부

- (다) 🔍 거부 이유별 건수에서 가장 많은 이유는 무엇이고, 이 숫자는 보안 담당에게 무엇을 알려 주나요?
  - 쓸 내용: ① 가장 많은 이유와 건수 ② 기록으로 확인되는 것과 확인되지 않는 것 ③ 보안 담당이 할 일
  - 답:
계정에 등록되지 않은 기기에서의 접속으로 총 2건
가장 많이 발생한 거부 이유는 계정에 등록되지 않은 기기에서의 접속으로 총 2건이다. 이는 분석 대상인 7건의 요청 중 2건이 등록되지 않은 기기에서 발생했음을 의미한다. 다만, 해당 기록만으로는 비정상 접속의 원인이 실제 공격인지, 기기 변경 등 정상적인 사유인지 확인할 수 없다. 따라서 보안 담당자는 관련 접속 기록과 기기 등록 상태를 확인하고, 해당 요청의 발생 경위를 점검해야 한다.

- (라) 🔍 등록 기기 · 국내 · 낮 시간에 MFA 까지 한 같은 계정이 20건 미만 조회를 100번 반복하면 이 코드는 어떻게 판정하나요? 왜 그런지, 이를 막으려면 무엇이 필요한지 적어 주세요.
  - 쓸 내용: ① 100번의 판정 결과 ② 그렇게 판정되는 이유 ③ 막으려면 필요한 것
