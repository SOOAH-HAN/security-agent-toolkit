## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:

```
def jitter(got):
    """
    응답 시간의 지터를 계산한다.
    입력: 응답을 받은 시간 리스트 got
    리턴: 이웃한 응답 시간 차이의 평균
    """
    total = 0

    for i in range(1, len(got)):
        total = total + abs(got[i] - got[i - 1])

    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:
회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %

- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답:
jitter 함수는 이웃한 응답 시간 차이의 절댓값을 모두 더한 뒤, 차이의 개수로 나눈 평균 지터값을 리턴한다
measure 함수 안의 jitter_value = jitter(got) 줄에서 jitter(got)을 호출하고, 리턴받은 값을 jitter_value 변수에 저장하여 출력할 때 사용한다.

  - 답:SaaS 접속 지연이 크게 증가한 구간은 4번 홉과 5번 홉 사이인 통신사 중계 장비와 해외 연결 지점 사이의 외부 구간으로 의심된다. tracert 결과 4번 홉의 6ms에서 5번 홉의 48ms로 지연이 42ms 증가했고, 이후에도 49ms와 50ms로 높게 유지되었다. 사내 공유기와 방화벽의 응답 시간은 각각 1ms와 2ms로 낮아 사내 구간보다는 외부 구간을 먼저 확인할 필요가 있다.

### 4. 한계와 다음 확인

- 이 진단으로 알 수 없는 것 하나와, 다음에 확인할 것 하나를 적어 주세요.
  - 쓸 내용: ① 알 수 없는 것(예: 한 시각의 값이라는 점) ② 다음 확인(시간대를 바꿔 다시 재기 · 구간 운영자에게 확인 요청)
  - 답:
한 시각의 측정 결과만으로는 일시적인 네트워크 혼잡인지 지속적인 문제인지 확정할 수 없다. 다른 시간대에 ping과 tracert를 다시 측정하고, 같은 구간에서 지연이 반복되면 해당 구간 운영자에게 측정값과 측정 시각을 전달해 확인을 요청한다.
