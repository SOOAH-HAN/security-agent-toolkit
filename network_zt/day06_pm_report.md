### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답:Docker version 29.8.2, build 7fc2dff

- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답:
① Docker 클라이언트가 사용자의 docker run hello-world 명령을 Docker 엔진에 전달한다.

② **Docker 엔진(Daemon)**은 로컬에 hello-world 이미지가 있는지 확인한다. 이미지가 없으면 Docker Hub에서 이미지를 내려받는다.

③ Docker 엔진이 내려받은 이미지를 바탕으로 컨테이너를 생성하고 실행한다.

④ 컨테이너 안에서 hello-world 프로그램이 실행되어 Hello from Docker! 메시지를 출력한다. 출력 결과는 Docker 클라이언트를 거쳐 터미널에 표시된다.

- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답:
① docker images에는 hello-world:latest 이미지가 표시되었다. 이미지는 컨테이너를 생성할 때 사용하는 프로그램 및 실행 환경의 묶음이다.

② docker ps -a에는 hello-world 이미지를 기반으로 생성된 컨테이너가 표시되었다. 컨테이너 ID는 347095f5ec21이고, 상태는 Exited (0)이다.

③ 이미지는 컨테이너를 만들기 위한 원본이고, 컨테이너는 그 이미지를 바탕으로 생성되어 프로그램을 실행하는 환경이다. 컨테이너가 종료되어도 이미지와 컨테이너 기록은 자동으로 삭제되지 않는다.

- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답:

```
① 실행 결과

IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   11a3eb1597e8       25.9kB         9.49kB    U

② 항목의 값과 뜻

IMAGE: hello-world:latest — 이미지 이름은 hello-world이고, latest는 이미지 태그이다.

ID: 11a3eb1597e8 — 이미지의 고유 ID를 짧게 표시한 값이다.

EXTRA: U — In Use를 뜻하며, 해당 이미지가 컨테이너에서 사용 중임을 나타내는 표시이다.

```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답:

```
### (마) `docker ps -a` 출력 및 항목 설명

① 실행 결과

```text

347095f5ec21   hello-world   "/hello"   About a minute ago   Exited (0) About a minute ago             musing_borg

② 항목의 값과 뜻

- **NAMES:** `musing_borg` — Docker가 컨테이너에 자동으로 부여한 이름이다.
- **IMAGE:** `hello-world` — 컨테이너를 생성할 때 사용한 이미지의 이름이다.
```

## 6교시 · nginx 서버 켜고 접속 기록 읽기

### 문제 6-1 · 포트 없이 켜 보고, 포트를 연결해 접속하고, 기록 읽기

- (가) 포트 없이 켠 `web` 에 접속했을 때 어떻게 되었는지 적어 주세요.
  - 쓸 내용: 접속했을 때 나온 화면이나 오류와 `docker ps` 의 PORTS 열
  - 답:
  포트 연결 옵션 `-p` 없이 nginx 컨테이너를 실행했을 때, `docker ps`의 PORTS 열에는 `80/tcp`만 표시되었다. 이는 컨테이너 내부의 80번 포트는 열려 있지만 내 PC의 포트와 연결되지 않았다는 뜻이다. 따라서 내 PC에서 `http://127.0.0.1:8080`으로 접속하면 포트 없이 실행한 컨테이너가 아니라, 8080번 포트에 연결된 기존 `web` 컨테이너에 접속하게 된다.

- (나) 🔍 `-p 8080:80` 이 하는 일을 내 PC의 포트와 컨테이너의 포트로 나눠 설명해 주세요.
  - 쓸 내용: ① 내 PC 쪽 포트 ② 컨테이너 쪽 포트 ③ 연결이 하는 일
  - 답:
① 내 PC 쪽 포트: 8080번 포트
② 컨테이너 쪽 포트: 80번 포트
③ 연결이 하는 일: 내 PC의 8080번 포트로 들어온 요청을 컨테이너의 80번 포트로 전달한다.

- (다) 🔍 `docker logs web` 출력에서 `GET /` 줄 하나를 붙여 넣고, 접속자 주소 · 시각 · 요청 · 응답 번호를 찾아 적어 주세요.
  - 쓸 내용: ① `GET /` 줄 ② 접속자 주소 · 시각 · 요청 · 응답 번호 네 가지
  - 답:

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답:
 ① 바꾼 뒤 화면: 컨테이너 안의 index.html 파일을 <h1>inside</h1>로 수정한 뒤 브라우저에서 inside가 표시되었다.

② 지우고 다시 켠 뒤 화면: docker rm -f web으로 기존 컨테이너를 삭제하고 새 컨테이너를 실행하자, 수정한 내용이 사라지고 원래의 Welcome to nginx! 화면이 표시되었다.
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답:
  ① 사라진 이유: 컨테이너 안에서 수정한 파일은 해당 컨테이너에 저장되기 때문에 컨테이너를 삭제하면 수정한 내용도 사라진다. 새 컨테이너는 이미지에 들어 있는 원래 파일로 시작한다.

② -v로 연결하면 달라지는 점: 내 PC의 site-one 폴더를 컨테이너의 /usr/share/nginx/html 폴더에 연결하면, nginx가 PC에 저장된 파일을 웹페이지로 보여 준다. 따라서 컨테이너를 삭제하고 다시 만들어도 PC에 있는 파일은 유지된다. 이번 실습에서는 :ro를 추가해 컨테이너에서 파일을 읽기만 할 수 있도록 설정했다.

- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답:
① 화면에 나온 것: 원래 의도한 site-one 페이지가 표시되지 않고, 기존 nginx 기본 화면이 표시되었다.

② 그렇게 된 이유: Windows의 Git Bash가 경로를 자동으로 변환해 컨테이너 내부 경로가 잘못 전달되었기 때문이다. MSYS_NO_PATHCONV=1을 붙이면 경로 자동 변환을 막아 PC 폴더와 컨테이너 폴더를 올바르게 연결할 수 있다.
### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답:
http://127.0.0.1:8080 : site-one — 첫 번째 서버입니다
http://127.0.0.1:8081 : site-two — 두 번째 서버입니다

- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답:
  내 PC와 연결된 포트 번호가 다르다는 점이다. web-one은 8080->80/tcp, web-two는 8081->80/tcp로 표시된다. 두 컨테이너 모두 내부 포트는 80번이지만, PC에서 접속하는 포트 번호로 서버를 구분할 수 있다.

- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답::ro는 읽기 전용(Read Only)을 뜻한다. 컨테이너에서 연결된 파일을 임의로 수정하지 못하게 하고, PC에 있는 원본 파일을 안전하게 유지하기 위해 사용한다.
