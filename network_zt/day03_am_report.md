## 2교시 · nslookup

### 문제 2-1 · 도메인 이름을 IP 주소로 — 두 DNS 서버에 묻기

- (가-1) 처음 `nslookup example.com` 을 쳤을 때, 내가 물어본 DNS 서버의 주소와 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: 화면 맨 위 `Address` 줄의 주소 하나, 아래쪽 `Addresses` 에서 숫자 네 개를 점으로 이은 주소 하나 — 두 개를 「서버: … / example.com: …」처럼. 맥북은 맨 위 `Address`, 아래 `Name:` 다음 `Address` 줄
  - 답: 
  서버: 168.126.63.1 / example.com: 172.66.147.243

- (가-2) `nslookup example.com 8.8.8.8` 을 쳤을 때, 맨 위 `서버` 줄에 나온 이름과 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: `서버` 줄의 이름 하나(맥북은 `Server`), IPv4 주소 하나. 시간 초과가 났으면 「시간 초과」라고 적어도 됩니다
  - 답:
  서버: dns.google /
  DNS 서버 IP: 8.8.8.8 /
  example.com: 104.20.23.154

- (나) 🔍 화면 위쪽 `Address` 와 아래쪽 `Addresses` 는 각각 무엇의 주소일까요? 두 화면을 비교해서 적어 주세요.
  - 쓸 내용: ① 두 화면에서 바뀐 쪽과 그대로인 쪽 ② 그렇게 된 이유 — 위쪽 · 아래쪽이 각각 무엇의 주소인지를 근거로 쓰기
  - 답:위쪽 Address는 내 PC가 질문을 보낸 DNS 서버의 IP 주소이고,아래쪽 Addresses는 조회한 도메인인 example.com에 해당하는 IP 주소이다.두 화면을 비교하면 위쪽 DNS 서버 주소는 168.126.63.1에서 8.8.8.8로 바뀌었지만, 아래쪽 도메인의 IPv4 주소는 172.66.147.243과 104.20.23.154로 동일하게 확인되었다. DNS 서버를 다르게 지정했기 때문이다.

- (다-1) 회사 PC 가 회사 DNS 서버 대신 `8.8.8.8` 같은 외부 DNS 서버에 직접 묻고 있다면, 관제 담당자는 왜 이것을 확인해야 할까요?
  - 쓸 내용: ① 회사 DNS 서버가 평소에 하는 일(검색해서 찾아도 됩니다) ② 외부 DNS 에 직접 물으면 그 일을 거치지 않게 되는 까닭
  - 답:회사 DNS 서버는 도메인의 IP 주소를 찾아 주는 것뿐 아니라 회사의 내부 도메인을 처리하고 DNS 조회 기록을 남기거나 보안 정책에 따라 위험한 도메인의 접속을 차단하는 역할을 할 수 있다. 회사 PC가 8.8.8.8 같은 외부 DNS 서버에 직접 질문하면 회사 DNS 서버의 기록이나 필터링 정책을 거치지 않을 수 있다. 따라서 관제 담당자는 보안 정책을 우회하는 행위인지, 악성 도메인 접속이나 정보 유출과 관련된 활동인지 확인해야 한다.

- (다-2) 내 PC 의 DNS 서버 설정이 나도 모르게 낯선 주소로 바뀌어 있다면, 어떤 일이 생길 수 있을까요?
  - 쓸 내용: ① 그 낯선 DNS 서버가 내 질문에 어떤 답을 줄 수 있는지 ② 그 답 때문에 내가 어디로 접속하게 되는지
 - 답:
낯선 DNS 서버가 잘못된 IP 주소를 알려 주거나, 정상적인 사이트 대신 공격자가 만든 가짜 사이트의 IP 주소를 알려 줄 수 있다. 그러면 사용자는 정상적인 주소를 입력했더라도 가짜 로그인 페이지 등으로 연결되어 계정이나 비밀번호를 빼앗길 수 있다.
다만 DNS 설정이 낯설다는 사실만으로 공격이라고 단정하지 말고, 해당 서버가 정당한 서버인지 확인해야 한다.
### 문제 2-2 · URL 에서 이름을 꺼내 묻기 — 없는 이름이면

- (가-1) `day03_2-2_url_example.py` 를 실행했을 때 나온 두 줄을 그대로 옮겨 적어 주세요.

  - 쓸 내용: 에러 이름은 마지막 줄의 `:` 앞부분 하나, `nslookup` 문구는 `Non-existent domain` 이 든 줄 하나(맥북은 `NXDOMAIN` 이 든 줄)
- 답:에러 이름: socket.gaierror
nslookup 결과: Non-existent domain이 포함된 실제 출력 줄을 추가로 확인해야 한다.

- (나-1) `parts[2]` 를 꺼냈더니 도메인 이름이 나왔습니다. 왜 번호 2 칸에 도메인 이름이 있을까요?
  - 쓸 내용: ① (가-1) 첫 줄의 리스트를 0 번부터 세어 각 칸에 무엇이 있는지 ② `//` 사이에 무엇이 생겼는지
  - 답:URL을 / 기호로 나누면 ['https:', '', 'example.com', 'news', 'today']라는 리스트가 만들어진다. 리스트는 0번부터 시작하므로 parts[0]은 https:, parts[1]은 빈 문자열, parts[2]는 example.com이다. https://에서 // 사이에 내용이 없어서 빈 문자열이 생기기 때문에 도메인 이름이 2번 칸에 들어간다.
- (나-2) 두 번째 파일은 왜 마지막 줄에서 에러가 나며 멈췄을까요? `nslookup` 결과와 이어서 적어 주세요.
  - 쓸 내용: ① `gethostbyname()` 이 DNS 서버에 무엇을 물었는지 ② DNS 서버가 어떤 답을 했는지 ③ 그래서 왜 에러가 났는지
  - 답:gethostbyname()은 abc.nowhere-not-exist.com의 IPv4 주소를 찾기 위해 DNS 조회를 요청한다. 하지만 해당 도메인의 주소를 찾지 못하면 Python에서 socket.gaierror가 발생한다. 따라서 IP 주소를 출력하는 부분에서 프로그램이 멈췄다.

- (다) 🔍 `Non-existent domain`(NXDOMAIN) 이 나왔다고 인터넷이 끊긴 걸까요? 아니라면 왜 아닌지 적어 주세요.
  - 쓸 내용: ① DNS 서버가 답을 했는지 안 했는지 ② 인터넷이 정말 끊겼다면 화면이 어떻게 달랐을지
  - 답:아니다. NXDOMAIN은 DNS 서버가 요청을 받고 해당 도메인이 존재하지 않는다고 응답했다는 뜻이다. 인터넷 연결이 완전히 끊겼다면 DNS 서버에 연결하지 못하거나 요청 시간이 초과되는 등의 다른 결과가 나타날 수 있다. 따라서 존재하지 않는 도메인과 인터넷 연결 장애는 구분해야 한다.

- (다-1) (가-2) 에서 본 것처럼 한 도메인에 네임서버를 둘 이상 두는 이유는 무엇일까요?
  - 쓸 내용: 네임서버가 하나뿐일 때 그 서버가 멈추면 무슨 일이 생기는지
  - 답:네임서버가 하나뿐인데 그 서버가 고장 나거나 응답하지 않으면 도메인의 DNS 정보를 조회하기 어려워질 수 있다. 여러 네임서버를 두면 한 서버에 장애가 발생해도 다른 서버가 응답할 수 있어 DNS 서비스를 더 안정적으로 운영할 수 있다.

- (다-2) 어떤 회사 도메인의 네임서버가 갑자기 낯선 서버로 바뀌었다면, 어떤 일이 생길 수 있을까요?
  - 쓸 내용: ① 권한 있는 네임서버가 그 도메인에 대해 정하는 것 ② 그 서버를 공격자가 관리하게 되면 웹 · 메일 접속이 어떻게 되는지
  - 답:권한 있는 네임서버는 도메인의 IP 주소 등 DNS 레코드 정보를 관리한다.공격자가 네임서버를 관리하게 되면 정상적인 웹사이트나 메일 서버 대신 공격자가 지정한 주소를 알려 줄 수 있다. 그 결과 사용자가 가짜 웹사이트에 접속하거나 메일이 공격자가 관리하는 서버로 전달되어 정보가 유출될 수 있다. 따라서 네임서버 변경이 정당한 작업인지 확인해야 한다.

### 문제 4-1 · 메일 서버와 별칭 — MX · CNAME

- (가-1) `nslookup -type=mx google.com` 에서 메일 서버 이름(`mail exchanger =` 뒤)과 우선순위 숫자(`MX preference`)를 적어 주세요.

- (가-2) `nslookup www.naver.com` 에서 `Aliases:` 줄의 이름과 `이름:` 줄의 최종 이름을 적어 주세요.
  - 쓸 내용: `Aliases:` 에 나온 이름, `이름:` 에 나온 이름. 맥북은 `canonical name =` 뒤가 최종 이름입니다
  - 답:이름:    www.naver.com.nheos.com
Addresses:  223.130.200.219
            223.130.192.247
            223.130.192.248
            223.130.200.236
Aliases:  www.naver.com

- (나-1) MX 레코드는 왜 IP 가 아니라 서버 이름으로 답할까요? 그 서버의 IP 는 어떻게 알아낼까요?
  - 쓸 내용: ① 서버 이름으로 적어 두면 좋은 점(서버 IP 가 바뀌는 경우를 생각해 보세요) ② IP 를 알아내는 방법(안내 4.1 절의 표 참고)
  - 답:MX 레코드는 메일을 받을 서버를 이름으로 지정한다. 서버의 IP 주소가 바뀌더라도 서버 이름을 유지할 수 있기 때문이다. 메일 서버의 IP 주소는 MX 레코드에서 확인한 서버 이름을 대상으로 nslookup smtp.google.com을 실행해 조회할 수 있다.

- (나-2) `www.naver.com` 은 왜 다른 이름(정식 이름)을 가리키고 있을까요?
  - 쓸 내용: ① CDN 이 무엇인지 한 줄 ② 큰 사이트가 CNAME 으로 CDN 이름을 가리키게 하는 까닭
  - 답:도메인의 별칭을 실제 서비스에 연결하기 위해서다. 서비스 운영자는 별칭과 정식 이름을 분리해 서버 구성이나 서비스 제공 방식을 관리할 수 있다. 따라서 다른 이름을 가리킨다는 사실만으로 비정상적인 사이트라고 판단할 수 없다.

- (다) 🔍 의심스러운 메일을 받았을 때, 보낸 쪽 도메인의 MX 레코드를 확인하면 무엇을 알 수 있을까요?
  - 쓸 내용: ① 정상 회사 도메인의 MX 는 보통 어떤지 ② MX 가 없거나 낯설면 무엇을 의심할 수 있는지
  - 답:해당 도메인에 설정된 메일 수신 서버의 이름과 우선순위를 확인할 수 있다. 이를 통해 메일 서버 설정이 예상한 내용과 일치하는지 추가로 확인할 수 있다. 다만 MX 레코드가 존재한다는 사실만으로 발신자가 진짜인지 또는 메일이 안전한지 확정할 수는 없다.

### 문제 4-2 · 내 PC 의 DNS 캐시와 TTL

- (가-1) `ipconfig //displaydns` 에서 본 `example.com` 의 TTL 숫자와, `//flushdns` 뒤에 그 항목이 남아 있었는지 적어 주세요.
  - 쓸 내용: 숫자 하나와 「남음 / 없어짐」 하나. 맥북은 「건너뜀」, 「표시할 수 없습니다」가 나오면 옆 사람 화면의 값
- 답:TTL 숫자: 26초
ipconfig //flushdns 실행 후: 없어짐

- (가-2) `day03_4-2_ttl_60.py`(`ttl = 60`)를 실행했을 때 나온 네 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 네 줄을 복사해 붙여 넣기
  - 답:
30 초: 캐시의 답을 쓴다
100 초: DNS 서버에 새로 묻는다
299 초: DNS 서버에 새로 묻는다

- (나) 첫 파일과 두 번째 파일에서 100초 줄의 결과가 다릅니다. 왜 그럴까요?
  - 쓸 내용: ① 두 파일의 만료 시각(저장한 시각 + TTL)을 각각 계산 ② 100 이 각 만료 시각보다 작은지 큰지
  - 답:첫 번째 파일의 TTL은 300초이고 두 번째 파일의 TTL은 60초이다. 두 파일 모두 saved_at = 0이므로 첫 번째 파일의 만료 시각은 300초, 두 번째 파일의 만료 시각은 60초이다. 100초는 300초보다 작으므로 첫 번째 파일에서는 캐시의 답을 사용하지만, 60초보다 크므로 두 번째 파일에서는 DNS 서버에 새로 묻는다.

- (다-1) 🔍 사이트가 서버 IP 를 바꿨는데도, 한동안은 옛 IP 로 접속되는 사람이 있습니다. 왜 그럴까요?
  - 쓸 내용: ① 캐시에 무엇이 저장되는지 ② TTL 이 지나기 전에는 어떻게 동작하는지
  - 답:DNS 캐시에는 도메인 이름과 그에 대응하는 IP 주소가 저장된다. 사이트의 IP 주소가 변경되어도 PC의 캐시 TTL이 만료되기 전에는 기존 IP 주소를 계속 사용할 수 있으므로 한동안 옛 IP로 접속될 수 있다.
  
- (다-2) 어떤 PC 가 계속 이상한 주소로 접속된다면, 관제 담당자는 왜 `ipconfig //flushdns` 부터 해 볼까요?
  - 쓸 내용: ① 캐시에 어떤 답이 남아 있을 수 있는지 ② 비운 뒤에는 PC 가 어떻게 다시 묻는지
  - 답:PC의 DNS 캐시에 오래되었거나 잘못된 IP 주소가 남아 있을 수 있기 때문이다. 캐시를 비우면 PC가 다시 DNS를 조회할 때 새로운 응답을 받을 수 있다. 다만 DNS 서버 자체에 잘못된 기록이 있다면 추가 점검이 필요하다.
