## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:
$ python warmup_2_1.py
192 11000000
168 10101000
10 00001010
25 00011001
$ python warmup_2_1b.py
192 11000000
168 10101000
100 01100100
134 10000110
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답:10진수 숫자를 2진수로 변환하고, 결과가 8자리가 되도록 앞에 0을 채운다. 예를 들어 100은 01100100으로 출력된다.
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답:1010으로 출력된다. 앞에 0을 채워 8자리로 만드는 기능이 없기 때문이다.
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답:IPv4 주소는 8비트씩 네 부분으로 구성되어 총 32비트이므로, 각 부분을 8자리로 맞추면 주소의 구조를 쉽게 확인할 수 있다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답:IPv4 주소는 숫자 네 부분으로 구성되며, 각 부분은 8비트로 표현된다. 따라서 전체 크기는 8비트 × 4 = 32비트이다. 8비트는 0과 1로 만들 수 있는 조합이 2⁸ = 256가지이므로, 각 부분은 0부터 255까지의 숫자로 표현된다.
- (다-2) 32비트로 만들 수 있는 주소의 개수:IPv4 주소는 총 32비트이며, 각 비트는 0 또는 1의 두 가지 값을 가질 수 있다. 따라서 가능한 IPv4 주소의 수는 2³² = 4,294,967,296개이며, 약 43억 개이다.
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답:**(다-3) IPv4 주소 개수 계산 과정**

IPv4 주소는 총 32비트로 구성된다. 각 비트는 0 또는 1의 두 가지 값을 가질 수 있으므로, 가능한 조합의 수는 2를 32번 곱한 \(2^{32}\)이다. 따라서 총 4,294,967,296개의 주소를 표현할 수 있다.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - IPv4 주소는 개수가 한정되어 있어 모든 기기에 공인 IP 주소를 하나씩 주기 어렵다. 그래서 집이나 회사에서는 기기마다 사설 IP 주소를 사용한다. 공유기는 NAT 기능을 이용해 사설 IP 주소를 공인 IP 주소로 변환해 인터넷과 통신하도록 한다. 특히 PAT를 이용하면 여러 기기가 공인 IP 주소 하나를 함께 사용할 수 있어 공인 IP 주소를 절약할 수 있다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 ipconfig로 확인한 내 IPv4 주소: 192.168.100.134
curl https://api.ipify.org로 확인한 공인 IP 주소: 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답:192.168.100.134는 사설 IP이다. 사설 IP 주소 범위인 192.168.0.0부터 192.168.255.255 사이에 포함되기 때문이다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답:1.245.252.171은 사설 IP 주소의 세 가지 범위에 포함되지 않으므로 공인 IP 주소로 볼 수 있다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답:172.20.5.6은 사설 IP 주소 범위인 172.16.0.0~172.31.255.255에 포함되므로 내부망 장비의 주소로 분류한다. 반면 172.32.5.6은 해당 범위에 포함되지 않으므로 사설 IP가 아닌 주소로 분류한다.

- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답:회사나 집에서는 여러 PC가 사설 IP 주소를 사용하고, 공유기나 NAT 장비를 통해 하나의 공인 IP 주소로 인터넷에 접속할 수 있다. 따라서 외부 서버 로그에 같은 공인 IP 주소가 기록되어 있더라도 어떤 내부 PC가 접속했는지 IP 주소만으로는 구분하기 어렵다. 내부 PC를 확인하려면 접속 시간과 포트 번호, NAT 장비의 주소·포트 변환 로그 등을 함께 확인해야 한다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답:정적 NAT는 사설 IP 주소와 공인 IP 주소를 미리 정해진 방식으로 1:1 연결하는 것이다. 따라서 외부에서 내부 서버에 접속할 때처럼 항상 같은 공인 IP 주소를 사용해야 하는 경우에 적합하다.
  동적 NAT는 여러 공인 IP 주소를 모아 둔 주소 풀에서 필요한 주소를 선택해 사설 IP 주소와 연결하는 것이다. 연결에 사용할 공인 IP 주소가 고정되어 있지 않고, 사용할 수 있는 주소 풀의 상황에 따라 달라질 수 있다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
- 답:여러 직원 PC가 인터넷을 사용할 때는 일반적으로 PAT를 이용해 여러 사설 IP 주소가 하나의 공인 IP 주소를 함께 사용하도록 한다. PAT는 포트 번호를 함께 사용해 각 연결을 구분한다.
따라서 외부 서버의 로그에 같은 공인 IP 주소가 기록되어 있어도 어떤 직원 PC에서 접속했는지 바로 알 수는 없다. 해당 PC를 확인하려면 접속 시간, 출발지 포트 등의 정보와 NAT 장비에 기록된 주소·포트 변환 로그를 함께 확인해야 한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답:외부 사용자가 사내 웹 서버에 안정적으로 접속해야 한다면 정적 NAT처럼 고정된 공인 IP 주소와 내부 서버의 사설 IP 주소를 연결하는 방식이 적합하다. 이렇게 하면 외부 사용자가 일정한 공인 IP 주소를 통해 서버에 접속할 수 있다. 실제 환경에서는 방화벽 정책과 포트 포워딩 설정도 함께 고려해야 한다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:

---집이나 회사 안에서 사용하는 사설 IP와 인터넷에서 사용하는 공인 IP가 다르다는 것을 알았다. 또한 NAT는 사설 IP와 공인 IP 사이에서 주소를 바꿔 주고, PAT는 포트 번호를 이용해 여러 기기의 통신을 구분하면서 공인 IP 하나를 함께 사용할 수 있게 한다는 것을 배웠다. 외부 서버 로그에 같은 공인 IP가 기록되어도 접속 시간과 포트 번호, NAT 변환 로그를 함께 확인해야 내부 PC를 구분할 수 있다는 점도 알게 되었다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수:
255.255.0.0
/16
/전체 65,536개 · 사용 가능한 호스트 주소 65,534개
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분:
망 부분은 192.168, 
장비 부분은 100.134
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답:서브넷 마스크 255.255.0.0을 2진수로 나타내면 11111111.11111111.00000000.00000000이다. 1인 비트는 망 부분을, 0인 비트는 장비 부분을 가리킨다. 마스크에서 1이 8개인 255가 두 묶음이므로 1은 총 16개이며, IP 주소의 앞 두 묶음인 192.168이 망 부분이고 뒤 두 묶음인 100.134가 장비 부분이다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답:서브넷 마스크 255.255.0.0에서 255는 2진수로 11111111이며, 1이 8개인 묶음이다. 255가 두 묶음이므로 1의 개수는 8 × 2 = 16개이다. 따라서 CIDR 표기는 /16이다.
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답:내 PC의 IP 주소는 192.168.100.134이고 서브넷 마스크는 255.255.0.0이다. 같은 교실의 다른 PC도 같은 서브넷 마스크를 사용하고 망 부분이 192.168로 같다면, 두 PC는 같은 망에 속한다. 이때 망 부분은 같지만 각 PC를 구별해야 하므로 장비 부분은 다를 수 있다. 즉, ‘같은 망’이란 IP 주소의 망 부분이 같아 동일한 네트워크 범위에 속한다는 뜻이다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답:내 서브넷 마스크는 255.255.0.0이므로 앞의 두 묶음인 망 부분을 비교한다. 192.168.10.25와 192.168.20.25는 모두 망 부분이 192.168로 같으므로 같은 망에 속한다. 세 번째와 네 번째 묶음은 장비 부분이므로 서로 달라도 같은 망일 수 있다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답:서브넷 마스크를 /24(255.255.255.0)로 변경하면 앞의 세 묶음이 망 부분이 된다. 192.168.10.25와 192.168.20.25는 세 번째 묶음이 각각 10과 20으로 다르므로 서로 다른 망에 속한다. 따라서 /16에서는 같은 망이었던 두 주소가 /24에서는 서로 다른 망으로 판정된다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답:서브넷 마스크에 따라 IP 주소가 같은 망인지 다른 망인지 판정하는 결과가 달라질 수 있다. 이 판정은 목적지로 데이터를 직접 보낼지 게이트웨이를 거쳐 보낼지 결정하는 통신 경로(라우팅)에 영향을 준다. 또한 방화벽 규칙을 설정할 때도 허용하거나 차단할 IP 주소와 네트워크 범위를 정확하게 지정해야 한다. 따라서 올바른 서브넷 마스크를 사용해야 통신 경로와 방화벽 규칙을 정확하게 설정할 수 있다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄:
255.255.0.0
192.168.0.0
192.168.255.255
- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지:
첫째 줄 255.255.0.0은 서브넷 마스크이고, 둘째 줄 192.168.0.0은 네트워크 주소이며, 셋째 줄 192.168.255.255는 브로드캐스트 주소이다. 서브넷 마스크는 망 부분과 장비 부분을 구분하고, 네트워크 주소와 브로드캐스트 주소는 내 망의 주소 범위를 나타낸다.
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디:
내 IPv4 주소 192.168.100.134와 비교하면 세 번째 마디 100과 네 번째 마디 134가 네트워크 주소에서는 0.0, 브로드캐스트 주소에서는 255.255로 바뀐다. 서브넷 마스크가 255.255.0.0이므로 앞의 두 마디는 망 부분이고 뒤의 두 마디는 장비 부분이기 때문이다.
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.

스위치의 MAC 주소 테이블에 목적지 주소가 있으면 해당 포트로만 전달하고, 없으면 들어온 포트를 제외한 나머지 포트로 전달하는 플러딩이 발생한다는 것을 알았다.

파이썬 딕셔너리에서 mac_table["AA"] = 1은 MAC 주소 AA를 키로, 포트 번호 1을 값으로 저장한다는 것을 배웠다. dest in mac_table로 목적지 주소가 등록되어 있는지도 확인할 수 있었다.

스위치는 프레임의 출발지 MAC 주소와 들어온 포트를 바탕으로 MAC 주소 테이블을 학습한다는 것을 알았다.

IP 주소와 MAC 주소의 역할이 다르다는 것을 배웠다. IP 주소는 최종 목적지까지 데이터를 전달하는 데 사용되고, MAC 주소는 각 네트워크 구간에서 프레임을 전달하는 데 사용된다.

ARP는 IP 주소에 대응하는 MAC 주소를 알아내는 데 사용하며, 외부 네트워크로 통신할 때는 일반적으로 외부 목적지의 MAC 주소가 아니라 기본 게이트웨이의 MAC 주소를 사용한다는 것을 실습으로 확인했다.

부서별로 VLAN을 분리하면 브로드캐스트 범위를 나눌 수 있고, 라우터의 접근 통제를 함께 적용해 다른 부서로의 불필요한 통신과 감염 확산 위험을 줄일 수 있다는 것을 알았다.

## 최종 설계서 — 7교시에 완성합니다

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.1 · 6.3

- 세 부서의 망 · VLAN · 게이트웨이:

운영팀: 192.168.20.0/24 · VLAN 20 · 게이트웨이 192.168.20.1
보안팀: 192.168.30.0/24 · VLAN 30 · 게이트웨이 192.168.30.1

- 부서마다 VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN 에 같은 서브넷을 주었을 때 PC 와 스위치가 각각 어떻게 동작하는지와 견주어 설명하세요.
- 답:부서마다 VLAN과 서브넷을 구분하면 각 부서의 네트워크를 분리하여 관리할 수 있다. 서로 다른 VLAN에 같은 서브넷을 설정하면 PC는 상대 PC를 같은 네트워크에 있다고 판단해 직접 통신하려고 하지만, 스위치는 VLAN을 분리하므로 ARP 요청이 다른 VLAN으로 전달되지 않는다. 따라서 정상적인 통신이 어려워질 수 있으므로 부서마다 VLAN과 서브넷을 하나씩 맞추어 설계한다.

### 2. 라우팅 경로 — 6-2

- 운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8` 이 지나는 장비와, 라우터가 그때 쓴 라우팅 표의 줄:
운영팀 PC에서 스위치를 거쳐 게이트웨이인 192.168.20.1에 도달하고, 라우터가 인터넷 쪽 라우터로 전달한다. 이때 목적지 8.8.8.8은 회사 내부 네트워크에 해당하지 않으므로 라우팅 표의 기본 경로인 0.0.0.0/0 → 인터넷 쪽 라우터를 사용한다.
- 라우터가 6-2 의 `192.168.30.5`(보안팀 PC)와 이 통신(`8.8.8.8`)에서 다음 홉을 다르게 고른 이유를, 라우팅 표에서 맞는 줄을 찾는 순서로 설명하세요.
  - 답:라우터는 목적지 IP 주소와 일치하는 라우팅 표의 경로를 찾는다. 192.168.30.5는 192.168.30.0/24에 속하므로 192.168.30.0/24 → 직접 연결 VLAN 30 경로를 선택한다. 반면 8.8.8.8은 회사 내부 서브넷과 일치하지 않으므로 기본 경로인 0.0.0.0/0 → 인터넷 쪽 라우터를 선택한다. 즉, 목적지 주소에 따라 일치하는 경로가 달라지기 때문에 다음 홉도 달라진다.
### 3. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유:
IP 주소와 서브넷 마스크를 함께 확인하여 같은 네트워크인지 판단하는 것이 중요하다고 생각한다. 서브넷 마스크에 따라 네트워크 범위가 달라지고, 이에 따라 PC가 직접 통신할지 게이트웨이를 거쳐야 할지가 결정되기 때문이다. 또한 VLAN과 서브넷을 부서별로 구분하고 라우팅 표를 확인하면 네트워크가 어떻게 연결되는지 이해할 수 있다는 것을 배웠다.
